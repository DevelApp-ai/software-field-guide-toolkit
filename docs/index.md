# Software Field Guide Toolkit

Companion tools for the book *The Software Field Guide* (DevelApp-ai/software-field-guide). `sfg` extracts architecture **truth from code** — not from what the diagrams claim — and renders editable, evidence-cited artifacts.

## The commands

Thirteen commands ship today, mapping to book issues [#54](https://github.com/DevelApp-ai/software-field-guide/issues/54), [#55](https://github.com/DevelApp-ai/software-field-guide/issues/55), [#58](https://github.com/DevelApp-ai/software-field-guide/issues/58), [#56](https://github.com/DevelApp-ai/software-field-guide/issues/56), [#60](https://github.com/DevelApp-ai/software-field-guide/issues/60), [#64](https://github.com/DevelApp-ai/software-field-guide/issues/64), [#66](https://github.com/DevelApp-ai/software-field-guide/issues/66), [#67](https://github.com/DevelApp-ai/software-field-guide/issues/67), [#68](https://github.com/DevelApp-ai/software-field-guide/issues/68), [#77](https://github.com/DevelApp-ai/software-field-guide/issues/77), [#78](https://github.com/DevelApp-ai/software-field-guide/issues/78), [#81](https://github.com/DevelApp-ai/software-field-guide/issues/81), and [#83](https://github.com/DevelApp-ai/software-field-guide/issues/83):

| Command | Book issue | What it does |
| --- | --- | --- |
| [`sfg context-map`](https://github.com/DevelApp-ai/software-field-guide-toolkit/blob/main/commands/context-map.md) | #54 Architecture context mapper and boundary doctor | Scans a .NET solution, builds the context dependency graph, and flags reach-arounds, forbidden directions, shared-kernel sprawl, and orphaned seams — every finding with file:line evidence. Emits an editable drawio map in the book's diagram conventions. |
| [`sfg seam-ledger`](https://github.com/DevelApp-ai/software-field-guide-toolkit/blob/main/commands/seam-ledger.md) | #55 Extension-point ledger and seam evidence linter | Inventories every seam (interfaces, plugin contracts, event hooks) with consumer counts, flags one-implementation seams as speculative generality, checks versioning and default implementations, and renders the collapse-review checklist. The evidence bar is a required input, never a guess. |
| [`sfg tenant-probes`](https://github.com/DevelApp-ai/software-field-guide-toolkit/blob/main/commands/tenant-probes.md) | #58 Multitenant isolation probe generator | Scans an EF Core model (DbContext, `DbSet<T>` entities) and generates a compilable xunit probe suite: cross-tenant read probes, fail-closed save guards, pool-checkout session-leakage checks, and disabled-state fail-closed probes — one `[Fact]` per entity, all citing the scanned file:line inventory. Runs in CI so isolation regresses loudly. |
| [`sfg cockpit`](https://github.com/DevelApp-ai/software-field-guide-toolkit/blob/main/commands/cockpit.md) | #56 Strangler-fig migration cockpit | Reads the migration route table (`migration.json`), checks it against the routing seam (every declared route wired; no undeclared wires), runs the sunset tripwire (a strangled route whose old-implementation traffic stayed under the retirement threshold for the full sunset window — or the fig is not finished), and generates a compilable shadow-diff xunit suite comparing old and new implementations per declared tolerance. |
| [`sfg events`](https://github.com/DevelApp-ai/software-field-guide-toolkit/blob/main/commands/events.md) | #60 Event contract conformance harness | Given a message contract (`events.json`), generates a compilable xunit suite that replays chaos-lite against the real consumer: duplicate delivery (exactly-once effects), out-of-order arrival, poison payloads (routed to the dead letters, never a crash), and old-schema producer replay (version-skew tolerance), plus outbox health checks on the producer side (publish waits pending; double dispatch stays idempotent). Seeded faults visibly fail a naive consumer and pass a compliant one — the #60 done-when. |
| [`sfg plan-audit`](https://github.com/DevelApp-ai/software-field-guide-toolkit/blob/main/commands/plan-audit.md) | #64 Plan-conformance auditor | Reconciles the approved spec diff (the intent PR's `.ai`/`.test` changes) against the generated code diff (the implementation PR) through a declared spec-to-code coverage map, and reports the two discrepancy classes — **omission** (an approved spec change no generated change implements) and **unapproved addition** (a generated change with no spec basis) — line-anchored on both sides, ranked errors-first and capped. Advisory by default; `--strict` exits non-zero on errors. LLM-assisted semantic matches are accepted only with valid anchors on both sides and are always labeled. |
| [`sfg eval`](https://github.com/DevelApp-ai/software-field-guide-toolkit/blob/main/commands/eval.md) | #66 LLM evaluation harness runner and baseline gate | Judges a **recorded** run (a committed `results.json`) against the suite's committed labeled set: aggregates per-stage metrics, calibrates the judge against the human-labeled sample (abstains never count as agreement), and gates against both the declared thresholds and the committed baseline — a regression cites the cases that moved, never just the aggregate. Dropped cases, undeclared cases, duplicate results, and stray metrics are loud errors. `--update-baseline` re-baselines deliberately. The harness never calls a model — wiring a live system means producing a results file in the documented format. |
| [`sfg migration-lint`](https://github.com/DevelApp-ai/software-field-guide-toolkit/blob/main/commands/migration-lint.md) | #67 Expand-migrate-contract migration linter | Parses the committed EF Core migration history, classifies every statement expand (additive), migrate (rewiring), or contract (removing/tightening), and checks each contract step against the gates ledger: a removal needs a gate pass with a measured window (expandedAt, then coldAt) and happens deliberately late. Flags destructive-first ordering (drop-then-reference, drop-then-re-add) and naive unbatched backfills. Advisory by default; `--strict` exits non-zero on errors. |
| [`sfg dora`](https://github.com/DevelApp-ai/software-field-guide-toolkit/blob/main/commands/dora.md) | #68 DORA four-key extractor | Extracts the DORA four keys from a **recorded** events export (deployments, changes, builds, failures) — it never calls an API live. Verifies every join the keys depend on (deployment → change → build, failure → restore evidence), flags re-runs mislabeled as new deployments (excluded from every count), and trends deployment frequency, lead time, change failure rate, and restore time per day, ISO week, or month against a versioned definitions file. Trends, not scores. Advisory by default; `--strict` exits non-zero on errors. |
| [`sfg review-calib`](https://github.com/DevelApp-ai/software-field-guide-toolkit/blob/main/commands/review-calib.md) | #77 Reviewer calibration harness | Measures the humans in the loop from a **recorded** export of review decisions — it never calls an API live and never ranks people. Computes catch rates on seeded defects per role, queue telemetry (approval rate and decision latency side by side — a queue that approves everything in under a second is a broken loop, not a review), and judge agreement on the recorded sample, and renders the rung-evidence table the autonomy ladder is earned on. Calibration instrument, not a leaderboard. Advisory by default; `--strict` exits non-zero on errors. |
| [`sfg bias-probe`](https://github.com/DevelApp-ai/software-field-guide-toolkit/blob/main/commands/bias-probe.md) | #78 Bias probe pack | Extends the #66 case format into a bias probe: counterfactual pairs (the same input with only the marker changed) must record the same dimension score — a deterministic consistency rate, not vibes; cohort-sliced metrics on the same baseline rail (the population is declared by cases, never guessed); refusal asymmetry (should-succeed cases must succeed for every cohort alike, and a must-refuse case that answers fails regardless of cohort); citation balance against declared corpus shares (advisory — the drift is published, an undeclared source cohort is an error); and judge calibration against a human-labeled sample, mandatory — abstentions never count. A regression cites the pairs and cases that moved. Advisory by default; `--strict` exits non-zero on errors. |
| [`sfg drills`](https://github.com/DevelApp-ai/software-field-guide-toolkit/blob/main/commands/drills.md) | #81 Resilience drill evidence harness | Judges a recorded drill export post-hoc against the committed scenario catalog: every alert fired inside its escalation clock, every restore met its RTO, the RPO data-loss window held, the expected telemetry signals are on the record, participants and component versions are named, and every scenario is drilled fresh — a DR plan on paper and a rehearsed one must not look alike. Judges recorded evidence only; it never injects failures (the #68 discipline). Staleness is measured against the export's recorded asOf instant, never the wall clock, so the analysis is deterministic. Advisory by default; `--strict` exits non-zero on errors. |
| [`sfg unit-econ`](https://github.com/DevelApp-ai/software-field-guide-toolkit/blob/main/commands/unit-econ.md) | #83 Cloud unit economics extractor | Joins a recorded billing export to a per-tenant allocation manifest and recorded request telemetry: cost-per-request trends per tenant and service, spend against declared per-period budgets, and a spend spike with per-tenant evidence. Every join is verified in both directions (the #68 discipline): an allocation rule must point at a billed service, a billed service must reach a tenant, a served service must be billed, a served tenant must be priced, and shares must sum to one. Trends, never scores — tenants are not ranked. Recorded exports only, never a live cloud API; a seeded estate is labeled SEEDED on every board. Advisory by default; `--strict` exits non-zero on errors. |

The two analysis commands share one syntax-level scan engine, so a seam in the ledger and a contract in the map are the same underlying type. The probe generator, the shadow-diff suite, and the event conformance suite are the tool's outputs that **compile against your code** — that is the point: the probes bite, or the isolation / migration / messaging claim is already broken.
